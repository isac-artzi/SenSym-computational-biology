Week 4 Plain-language companion

From $d'$ to an Error Rate, Explained Slowly

Where to draw the line · why the answer is $\Phi(d'/2)$ · what ROC curves and AUC mean · why we compare in $d'$, not in percent
This is the simplified companion to Week 4: the same ideas, slower, with more worked examples and fewer symbols. The labs, the full exercises, the Python assignment and the check-in list are in the original chapter. Open the full Week 4 chapter →
The whole week in one sentence If two cell types are $d'$ wobbles apart, the best you can do is draw the decision line halfway between them; each type's average then sits $d'/2$ wobbles from the line, and the bell-curve table $\Phi$ tells you the fraction of cells on the correct side: accuracy $= \Phi(d'/2)$.

1  Drawing the line

Take the standard marker gene: type 1 averages $\lambda_1 = 16.5$, type 2 averages $\lambda_2 = 12$. The simplest rule is a threshold: "if the count is above $t$, call it type 1".

Analogy · sorting apples and oranges by weight Apples average 150 g, oranges 180 g, and each varies by ±15 g or so. You put a single line on the scale: heavier than the line → orange. Put the line at 100 g and almost every apple is called an orange. Put it at 250 g and almost every orange is called an apple. Somewhere in between the total number of mistakes is smallest. When the two kinds are equally common and equally spread out, that best line is halfway: 165 g.

For the counts, the best rule is actually "pick whichever type makes this count more likely". For Poisson counts that rule is always a threshold, and it lands close to the middle — for $16.5$ vs $12$ the middle is $14.25$.

2  Why the answer is $\Phi(d'/2)$

For large-ish counts (roughly 10 or more), a Poisson count looks like a bell curve (a normal distribution) with the same mean and the same wobble $\sqrt{\lambda}$. That approximation is what turns $d'$ into a percentage.

The argument in four steps
  1. The two bell curves are centred $d'$ wobbles apart (that is what $d'$ means).
  2. The line is drawn halfway, so each centre is $d'/2$ wobbles from the line.
  3. A type-1 cell is classified correctly if its count lands on its own side of the line — that is, if it does not fall more than $d'/2$ wobbles below its average.
  4. For a bell curve, "the chance of landing below $z$ wobbles above the centre" is a standard table value called $\Phi(z)$. So the chance of being right is $\Phi(d'/2)$. By symmetry, the same is true for type 2.

$\Phi$ (capital "phi") is just the normal-distribution table from AP Statistics — the same thing as normalcdf(−1E99, z) on a TI-84. A few values to remember:

Worked example 1 · the standard marker gene
  1. From Week 3: $d' = 1.19$.
  2. Halve it: $d'/2 = 0.596$.
  3. Look up $\Phi(0.596) \approx 0.724$.
  4. So this one gene classifies about 72% of cells correctly.
Worked example 2 · going backwards

You want 97.7% accuracy from one gene. What $d'$ do you need?

  1. From the table, $\Phi(2) = 97.7\%$, so $d'/2 = 2$.
  2. So $d' = 4$.
  3. If the gene currently has $d' = 1$, you need $d'$ to go up 4×, which means depth up $4^2 = 16$×.

Three sanity checks that the formula passes, and that every formula you ever write should pass:

  • Identical types ($d' = 0$): $\Phi(0) = 50\%$ — a coin flip. Correct; nothing can do better.
  • Huge separation: $\Phi$ approaches 100% but never reaches it. Correct; a cell can always have a freak count.
  • More separation is never worse: $\Phi$ only goes up.
Try it · convert between $d'$ and accuracy
Type a $d'$ to get the accuracy, or type an accuracy (between 0.5 and 1) to get the $d'$ it needs.

4  ROC curves and AUC, without the jargon

A threshold is a trade-off. Move it down and you catch more type-1 cells, but you also wrongly catch more type-2 cells. The ROC curve draws every possible threshold at once:

  • across the bottom: the fraction of type-2 cells wrongly called type 1 ("false alarms"),
  • up the side: the fraction of type-1 cells correctly called type 1 ("hits").

A useless gene gives a diagonal line. A perfect gene hugs the top-left corner.

AUC in one sentence The AUC (area under the ROC curve) is the chance that a randomly picked type-1 cell has a higher count than a randomly picked type-2 cell (ties count as half). 0.5 = useless, 1.0 = perfect.
Worked example 3 · AUC by hand, tiny data

Type-1 counts: 5, 7, 9. Type-2 counts: 4, 6, 7. There are $3 \times 3 = 9$ pairs.

  1. 5 vs (4, 6, 7): wins, loses, loses → 1
  2. 7 vs (4, 6, 7): wins, wins, tie → 2.5
  3. 9 vs (4, 6, 7): wins, wins, wins → 3
  4. Total $= 6.5$ out of 9, so AUC $\approx 0.72$.
The $2$ versus $\sqrt{2}$ trap

For bell curves, accuracy $= \Phi(d'/2)$ but AUC $= \Phi(d'/\sqrt{2})$. Why different? Accuracy compares one noisy count to a fixed line. AUC compares two noisy counts to each other, and two sources of noise wobble more than one. For the standard gene: accuracy 72.4%, AUC 80.0%. Do not mix them up.

Ties are not an edge case here Counts are whole numbers, so two cells often have exactly the same count. If your code breaks ties by the order the cells happen to be listed in, you can get a very wrong AUC. At $\lambda = (1.5, 1.0)$ the honest AUC is about 0.62; break ties by file order and you might report 0.75. Always count a tie as half a win.

5  Why the course compares in $d'$, not in percent

Percentages bunch up near 100%, which hides big differences:

MethodAccuracy$d' = 2\,\Phi^{-1}(\text{accuracy})$
A98.0%4.11
B99.0%4.65

"One percentage point" sounds tiny. But in $d'$ it is a 13% difference, and since depth goes as $d'^2$, matching B with method A would need about 28% more sequencing. So: measure accuracy, convert to $d'$, compare there.

6  Check yourself

Quick check 1
A gene has $d' = 2$. What accuracy does it give? What AUC?
Show answer
Accuracy $= \Phi(1) = 84.1\%$. AUC $= \Phi(2/\sqrt2) = \Phi(1.414) \approx 92.1\%$.
Quick check 2
You need 93.3% accuracy. What $d'$ is that, and how much more depth do you need if you currently have $d' = 1.5$?
Show answer
$\Phi(1.5) = 93.3\%$, so $d'/2 = 1.5$ and $d' = 3$. That is 2× the current $d'$, so 4× the depth.
Quick check 3
Your code reports an exact error rate of 0.6 (60% wrong). What went wrong?
Show answer
The best possible rule can never be wrong more than 50% of the time — you could always ignore the data and flip a coin. Most likely you added the larger probability at each count instead of the smaller, or forgot the factor of ½. Test the identical-types case first: it must give exactly 0.5.
